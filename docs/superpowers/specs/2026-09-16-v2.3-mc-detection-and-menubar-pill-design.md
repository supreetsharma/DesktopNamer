# Desktop Namer v2.3 — Mission Control Detection Fix + Menu Bar Background Pill — Design

**Date:** 2026-09-16
**Status:** Approved
**Scope:** One release, two items: (1) fix Mission Control name labels, which never appear on modern macOS; (2) a user-configurable background pill behind the desktop name in the menu bar.

## Item 1: Mission Control labels never appear (bug fix)

### Root cause (empirically confirmed on this machine, macOS 15 / Darwin 24.6)

`MissionControlOverlay` triggers off the Dock's `com.apple.expose.front.awake` / `.sleep` distributed notifications. A probe observing ALL distributed notifications while Mission Control was programmatically opened and closed captured **zero** matching notifications: Apple no longer posts them. The overlay's trigger is dead, so `showOverlays()` is never called — the feature has never worked on this OS version. The rendering and positioning code downstream of the trigger is healthy (shipped and reviewed in v2.1/v2.2).

### Replacement signal (empirically confirmed)

While Mission Control is up, the Dock owns on-screen windows it otherwise never has:

| State | Dock-owned on-screen windows |
|---|---|
| MC closed | wallpaper windows only, layer −2147483624 |
| MC open | + screen-sized windows at layers **18 and 20** (one set per display) |

Observed via `CGWindowListCopyWindowInfo([.optionOnScreenOnly], kCGNullWindowID)`. Window **names** are redacted without Screen Recording permission, but owner name, layer, and bounds are always available — the signature needs no permissions at all.

### Design

- **Poller:** `MissionControlOverlay` replaces its two distributed-notification observers with a repeating main-queue timer. Idle cadence 500 ms; while Mission Control is detected, 200 ms (prompt label removal on close). Each tick: one filtered `CGWindowListCopyWindowInfo` call (sub-millisecond) → classify.
- **Classifier (pure, in `DesktopNamerCore`):** `func isMissionControlActive(dockWindowLayers: [Int]) -> Bool` — the app side extracts Dock-owned on-screen windows' layers and hands them to Core; the classifier returns true when any layer is ≥ 0. Rationale: the Dock's persistent windows (wallpaper) sit at hugely negative layers, while its Mission Control windows were observed at layers 18/20 — `>= 0` excludes wallpaper and tolerates minor OS drift in the exact MC layer values. Unit-tested with fixtures matching the probe's before/during/after captures.
- **Edges:** rising edge → existing `onMissionControlActivated()` path (keeps the 0.4 s settle delay and `activationWork` debouncing); falling edge → existing `onMissionControlDeactivated()`. The AX-based and heuristic positioning strategies are unchanged.
- **Lifecycle:** timer invalidated in `deinit`. Poll cost at idle: ~2 calls/second of a filtered window query — negligible CPU/battery.
- **Never crash (Global Constraint):** the window list is `[[String: Any]]`; all field extraction uses conditional casts with safe defaults.

### Rejected alternatives

- **AX observer on the Dock process:** event-driven, but requires Accessibility permission, which is currently optional (only improves label positioning). Would make a core feature permission-gated.
- **Keep notifications + poll fallback:** preserves dead code for no benefit; the notifications fire on no supported macOS we can verify.

## Item 2: Menu bar background pill (feature)

One global background color behind the desktop name in the menu bar — the same color regardless of which desktop is active (like a menu bar timer showing `05:00` on a green pill).

### Design

- **Setting:** `com.desktopnamer.menuBarBackgroundHex` (String, one of the 8 `SpacePalette.presets`; absent/nil = no pill, current rendering unchanged). Configured in **Settings > General** via a swatch row ("Menu bar background:") reusing the 8-preset + "none" pattern from the per-space color picker.
- **Rendering:** when set, `StatusItemController.updateTitle()` renders the title as a single **capsule image** embedded in the attributed title via `NSTextAttachment`:
  - Capsule: fill = chosen color, corner radius = height/2, text padding ≈ 8 pt horizontal / 2 pt vertical, vertically centered against the menu bar via the attachment's bounds baseline offset.
  - Content inside the capsule: the current space's color dot (when that space has a color) followed by the name in semibold system font.
  - Text color: automatic black/white by background luminance — pure `SpacePalette.isLight(hex:) -> Bool` in Core using relative luminance (`0.2126 R + 0.7152 G + 0.0722 B > 0.6`), unit-tested (yellow → light/black text; blue, red, purple → dark/white text).
  - The status item's leading SF Symbol icon stays outside the pill (matches the reference screenshot, where only the text carries the pill).
- **When unset:** the existing v2.2 attributed-string path runs byte-identical.
- **Reactivity:** the Settings swatch writes UserDefaults and the status item re-renders (the controller re-reads the default inside its observation-tracked `updateTitle()`; a change notification or a direct re-render hook keeps it immediate — implementation plan decides the minimal wiring).

### Rejected alternatives

- **`.backgroundColor` string attribute:** square highlight, visibly not the rounded pill in the reference.
- **Custom NSView replacing the status item button content:** most control, most invasive; the attachment image achieves the target look without replacing AppKit's button behavior (highlighting, clicks, scroll events).

## Error handling

- Window-list extraction: conditional casts only; a malformed or empty list classifies as "not active" and, if labels are showing, removes them.
- Invalid/unknown stored hex: treated as unset (no pill), never a crash.

## Testing

Additions to the `desktop-namer-tests` runner (61 checks today):

1. **MC classifier** — fixtures mirroring the probe: wallpaper-only layers → inactive; layers including 18/20 → active; empty list → inactive; junk entries skipped.
2. **Luminance** — `isLight` over all 8 presets with expected black-/white-text verdicts, plus invalid hex → safe default (dark → white text).

Manual QA (human, pre-merge): three-finger-swipe Mission Control on 1 and 2 displays → labels appear under thumbnails and disappear on close; pill on/off in Settings, correct text contrast per color, chip + name inside the pill, icon outside; regression sweep of v2.2 surfaces.
