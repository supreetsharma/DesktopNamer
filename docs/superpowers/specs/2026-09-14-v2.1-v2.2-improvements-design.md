# Desktop Namer v2.1 / v2.2 Improvements — Design

**Date:** 2026-09-14
**Status:** Approved
**Scope:** Two phased releases. v2.1 = reliability + configurable shortcuts + menu bar prominence. v2.2 = per-space colors/icons, quick switcher, switch HUD, bigger Mission Control labels.

## Motivation

The app works but has four reliability problems and a set of navigation/visibility gaps:

1. **Hotkeys are observers, not owners.** `NSEvent.addGlobalMonitorForEvents` cannot consume events, so Ctrl+1–9 both switches the desktop *and* reaches the frontmost app (conflicts with terminals, games). It also silently does nothing without Accessibility permission.
2. **Hotkeys are hardcoded** — no way to remap or disable them.
3. **Switch race:** `switchToSpace` fires the CGS call after a fixed 0.1 s delay; occasionally the switch is dropped.
4. **Crash risk:** `CGSCopyManagedDisplaySpaces` result is force-cast (`as!`); a malformed reply from the private API crashes the app.

User-facing needs beyond fixes: better navigation (name-based quick switcher, scroll-to-cycle on the menu bar item) and a more prominent current-desktop label (menu bar styling, switch HUD, larger Mission Control labels).

## Approach (chosen: B, phased)

Replace SwiftUI `MenuBarExtra` with an AppKit `NSStatusItem`, and adopt the `sindresorhus/KeyboardShortcuts` package. Alternatives considered:

- **A — zero dependencies, keep MenuBarExtra:** rejected. `MenuBarExtra` cannot receive scroll events or attributed styling, and a correct shortcut-recorder control is disproportionately expensive to hand-roll.
- **B single-release:** rejected in favor of phasing; the existing GitHub-release update checker makes shipping twice cheap, and reliability fixes shouldn't wait on visual features.

`KeyboardShortcuts` is a small, no-transitive-dependency package layered over Carbon `RegisterEventHotKey` — the same API we would otherwise call directly — and provides the recorder UI, persistence, and conflict detection.

- `SpaceManager` remains the single source of truth; new UI components observe it.

## Data model

```swift
struct SpaceSettings: Codable, Equatable {
    var name: String?
    var colorHex: String?   // one of 8 presets, nil = none
    var symbol: String?     // SF Symbol name, nil = none
}
```

- Stored as JSON `Data` in UserDefaults under `com.desktopnamer.spaceSettings`, keyed by space UUID.
- **Migration:** on first launch with the new key absent, read the old `com.desktopnamer.spaceNames` `[String: String]` and convert each entry to `SpaceSettings(name:)`. The old key is never deleted (safe downgrade). If migration decoding fails, start with empty settings; never crash.

## v2.1 scope

### Shortcuts (fixes #1 and #2)
- `KeyboardShortcuts.Name` entries: `switchToSpace1`…`switchToSpace9` (defaults Ctrl+1–9), plus `quickSwitcher` reserved for v2.2 (default ⌥Space).
- Settings window lists all nine with recorder controls and a master "Enable desktop shortcuts" toggle.
- Delete `NSEvent` monitor code; events are consumed by Carbon registration, and no Accessibility permission is required for switching. (Accessibility remains optional, used only for Mission Control overlay AX positioning.)

### Switch reliability (fixes #3)
- Issue `CGSManagedDisplaySetCurrentSpace` immediately after `NSApp.deactivate()` on the next runloop turn (no fixed 0.1 s sleep).
- Verify: poll `CGSGetActiveSpace` at +150 ms; if unchanged, retry the CGS call once. No error UI — best effort, logged via `os.Logger`.

### Crash safety (fixes #4)
- `CGSCopyManagedDisplaySpaces` result is conditionally cast. On failure: log, keep the previous `spaces`/`displayGroups`, and leave the menu bar title as-is.

### Menu bar prominence
- `NSStatusItem` button uses an `NSAttributedString` title: current space name in `.semibold` system font, preceded by a filled color-chip circle when the space has a color (v2.1 renders the chip infrastructure; colors arrive in v2.2, so v2.1 shows name only).
- Scroll wheel over the status item cycles desktops (up = previous, down = next), wrap-around, debounced to one switch per 250 ms.

### Settings window
- Opened from the dropdown ("Settings…", ⌘,). Sections: Shortcuts (recorders + master toggle), General (Launch at Login — also stays in the dropdown; Show HUD toggle appears here in v2.2), Updates (Check for Updates button).

## v2.2 scope

### Per-space colors and icons
- 8 preset colors + "none"; optional SF Symbol chosen from a small curated grid (~20 symbols: laptopcomputer, envelope, music.note, globe, hammer, book, gamecontroller, etc.).
- Edited inline in the dropdown's rename mode (color swatches + symbol picker row).
- Rendered in: dropdown rows, menu bar chip (current space), quick switcher rows, HUD, Mission Control labels.

### Quick switcher
- Non-activating `NSPanel` (`.nonactivatingPanel`), centered on the active screen, summoned by the `quickSwitcher` shortcut (default ⌥Space, remappable/disableable).
- Text field with live fuzzy filtering over desktop names; ↑/↓ to select, Enter switches, Esc dismisses. Rows show color/symbol + name + "Space N" + display name when multi-monitor.
- Panel closes on focus loss.

### Switch HUD
- On `NSWorkspace.activeSpaceDidChangeNotification`, show a borderless, click-through window centered on the screen containing the new space: capsule with color/symbol + name, 24 pt medium text, fade in 0.1 s, hold 0.5 s, fade out 0.2 s.
- Always shown on every switch regardless of origin (menu, shortcut, quick switcher, trackpad gesture) — it is the confirmation. Toggle "Show name when switching desktops" in Settings (default on).

### Mission Control labels
- Font 12 pt → 16 pt, padding scaled up; capsule tinted with the space color at 85 % opacity (black fallback when no color); symbol shown before the name when set.

## Error handling

- All CGS interactions: guarded casts, `os.Logger` logging, keep last-known state. The app must never crash due to private-API drift.
- KeyboardShortcuts recorder handles conflict/validation UI itself.
- Migration failures fall back to defaults without data loss (old key retained).
- Update checker unchanged (out of scope) apart from extracting `isNewer` for testing.

## Testing

New SwiftPM test target `DesktopNamerTests`:

1. **Version comparison** — `isNewer` extracted to a pure function; cases: equal, patch/minor/major bumps, unequal lengths, `v` prefix already stripped upstream.
2. **Settings migration** — old-key dict → `SpaceSettings`; empty old key; corrupted new-key JSON.
3. **Space parsing** — the CGS-dictionary parsing in `SpaceManager.refresh()` extracted to a pure function `parseDisplaySpaces(_:savedSettings:activeSpace:screenNames:)`; fixtures for single display, multi-display, fullscreen spaces filtered (`type != 0`), missing keys.

Manual QA checklist (per release): Mission Control overlay on 1 and 2 displays, overlay after display hot-plug, scroll-to-cycle direction, shortcut capture vs. a terminal app, HUD on rapid switching.

## Release plan

- **v2.1**: shortcuts, switch reliability, crash safety, status item + scroll, Settings window, test target. Bump version, build, DMG, GitHub release, appcast entry.
- **v2.2**: colors/icons, quick switcher, HUD, Mission Control label upgrade. Same release mechanics.

## Out of scope

- Code signing / notarization / Homebrew cask (distribution track — separate effort).
- Auto-naming from open apps; new-space naming prompts; rename-from-Mission-Control.
- Persistent corner badge.
